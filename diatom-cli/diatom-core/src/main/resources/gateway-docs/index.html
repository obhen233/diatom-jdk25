Diatom Gateway — API 文档 / API Documentation

Gateway 与 Worker 之间通过 HTTP 通信，Worker 可用任何语言实现。 Communication between Gateway and Worker is via HTTP. Workers can be implemented in any language. Worker 只需实现 2 个必需接口即可接入。 A Worker only needs 2 required endpoints to connect.

鉴权 / Authentication

Gateway 与 Worker 之间的 HTTP 通信使用共享 Token 鉴权。所有 POST/PUT/DELETE 请求均需携带以下安全头。 Communication between Gateway and Worker uses shared-token authentication. All POST/PUT/DELETE requests MUST carry the following security headers.

Header必需说明
HeaderRequiredDescription
X-Diatom-Auth 必需 共享 Token。Gateway 与 Worker 配置相同的 diatom.auth.token。未配置时启动会自动生成随机 Token 并打印到控制台。 必需 / Required 共享 Token。Gateway 与 Worker 配置相同的 diatom.auth.token。未配置时启动会自动生成随机 Token 并打印到控制台。Shared token between Gateway and Worker. Auto-generated if diatom.auth.token is not configured.
X-Diatom-Instance-Id 必需 发送方实例 ID。用于标识请求来源，便于日志追踪和调试。 必需 / Required 发送方实例 ID。用于标识请求来源，便于日志追踪和调试。Sender instance ID for request tracing and debugging.
X-Diatom-Encryption 可选 Body 加密算法标识，如 AES-256。配置 diatom.encryption.key 后启用。未启用时值为 none。 可选 / Optional Body 加密算法标识，如 AES-256。配置 diatom.encryption.key 后启用。未启用时值为 none。Body encryption algorithm identifier. Enabled when diatom.encryption.key is configured.
X-Diatom-Timestamp 可选 请求时间戳（毫秒），用于防重放。 可选 / Optional 请求时间戳（毫秒），用于防重放。Request timestamp (milliseconds) for anti-replay protection.

健康检查 (GET /worker/v1/health, GET /gateway/v1/health) 免鉴权。 Health check endpoints are exempt from authentication.

Worker → Gateway 接口 / Worker to Gateway

Worker 主动向 Gateway 发起的请求。Worker 启动后应先注册，然后周期性心跳。Requests from Worker to Gateway: register first, then heartbeat periodically.

POST /gateway/v1/workers Worker → Gateway ▶

Worker 启动时向 Gateway 注册自身信息。Gateway 将 Worker 加入注册表并可路由任务。Register a worker to the Gateway, enabling task routing.

头部值
头部 / Header值 / Value
Content-Typeapplication/json
X-Diatom-Auth<auth-token> 可选
X-Diatom-Auth<auth-token> 可选 / Optional

Request Body

{
  "workerId": "worker01",
  "host": "127.0.0.1",
  "port": 7001,
  "model": "claude-sonnet-4-6",
  "workspace": "D:/projects/my-project",
  "tier": "default",
  "group": "my-group",
  "useSsl: false,
  "status": "ONLINE",
  "lastHeartbeat: 1700000000000,
  "currentLoad: 0.0,
  "pid: 12345,
  "registeredAt: 1700000000000

workspace: Worker 的实际工作目录。默认与 Gateway 同步，可通过 -Dworkspace.dir 自定义。Real workspace directory. Syncs from Gateway by default; override with -Dworkspace.dir.

  "status": "registered",

PUT /gateway/v1/workers/{workerId}/heartbeat Worker → Gateway ▶

Worker 周期性向 Gateway 发送心跳。Gateway 在心跳超时（60s 离线，30s 可疑）后将 Worker 标记为 OFFLINE 或 SUSPECT。Periodic heartbeat to maintain online status. Timeout: 60s → OFFLINE, 30s → SUSPECT.

Request Body

{
  "currentLoad": 0.0,
  "activeTasks": 0
}

Response 200

{
  "status": "ok"
}

POST /api/v1/task Gateway → Worker 必需 必需 / Required ▶

Gateway 将任务分发给 Worker。支持两种响应模式。Gateway dispatches a task to the Worker. Two response modes:

  • 同步模式（Response 200）：Worker 在 HTTP 响应中直接返回完整结果
  • 异步模式（Response 202）：Worker 先确认接收，完成后通过 callback 上报结果
  • 同步模式 / Sync（Response 200）：Worker 在 HTTP 响应中直接返回完整结果 / Worker returns the complete result directly in the HTTP response.
  • 异步模式 / Async（Response 202）：Worker 先确认接收，完成后通过 callback 上报结果 / Worker acknowledges receipt first, then reports results via callback.

快速接入指南 / Quick Start

实现一个 Worker 只需以下步骤。A Worker needs only these steps to connect.

最小实现 / Minimum Requirements

1. GET /api/v1/health — 返回 Worker 健康状态 / Worker health status
2. POST /api/v1/task — 接收任务并执行 / Receive and execute tasks

启动流程 / Startup Flow

1. Worker 启动 HTTP Server（端口自定）/ Start HTTP server
2. POST /gateway/v1/workers → 向 Gateway 注册 / Register to Gateway
3. 定时 PUT /gateway/v1/workers/{id}/heartbeat → 心跳维持 / Heartbeat
4. Gateway 调用 POST /api/v1/task → Worker 开始执行 / Execute task
5. 执行完毕 → 同步返回结果 / Return result synchronously

Bridge 一键接入 / Bridge Auto-Connect

对于不支持 diatom 协议的 CLI 工具（claude, codex, opencode 等），使用 Bridge 工具自动包装。For CLI tools without native diatom protocol support.

bridge --tool claude --gateway http://gateway:8080 --port 9001

Bridge 会自动处理：HTTP 服务、注册、心跳、CLI 子进程管理、输出解析。Auto-handles HTTP server, registration, heartbeat, CLI management, output parsing.

最小 Worker 示例 / Minimal Worker Example (Python)

from flask import Flask, request, jsonify
import time

app = Flask(__name__)

@app.route('/api/v1/health')
def health():
    return jsonify({"status": "healthy", "workerId": "my-worker"})

@app.route('/api/v1/task', methods=['POST'])
def execute_task():
    task = request.json
    instruction = task['instruction']
    # 调用你的 AI Agent 执行任务 / Execute with your AI Agent
    result = run_my_agent(instruction)
    # 同步返回结果 / Return synchronously
    return jsonify({
        "ok": True,
        "taskId": task['taskId'],
        "status": "completed",
        "result": {
            "taskId": task['taskId'],
            "status": "success",
            "summary": f"Done: {instruction}",
            "changes": result.get('changes', [])
        }
    })

if __name__ == '__main__':
    app.run(port=9001)
